# 应急车道车牌取证 —— 使用规则

## 一、每次使用前必须向用户索取以下三项

| # | 项目 | 要求 |
|---|------|------|
| 1 | **视频源** | 待检测的视频文件路径 |
| 2 | **ROI 参考图片** | 用户在视频截图上用**红色**划出应急车道区域（画线或画闭合区域均可） |
| 3 | **初成果存放路径** | **路径不得包含中文**。<br>该目录用于存放检测产出：`检测结果.csv`、`检测结果.json`、`证据图/` |

> ROI 必须逐视频重新标定。不同视频的应急车道在画面中的位置不同；实测自动识别车道线不可靠
> （一次偏右 210px，一次拟合出斜率 -6.19 的荒谬线），因此**由用户在截图上划定**是最稳妥的方式。

## 二、检测流程（固定顺序，不可颠倒）

```
① 解析 ROI        用户在截图上的红线 → 归一化多边形（凸包重排，避免自相交）
② 车辆检测        YOLO 通用车辆检测 —— 不依赖车牌可见性，保证"有没有车"能判对
③ ROI 归属判定    车辆底边与应急车道多边形的重叠比例 ≥ 阈值才记录
④ 车辆跟踪        给车辆稳定 ID，聚合多帧证据
⑤ 车牌识别        对**已判定在 ROI 内**的车辆，取其区域送 HyperLPR3
⑥ 分级输出        CONFIRMED / SUSPECT（需人工确认）/ UNREADABLE
```

### 两条硬约束（务必遵守）

1. **只记录出现在 ROI 区域内的车辆。**
2. **确定车辆后，只将 ROI 范围内的图形内容送去车牌检测器。**
   —— 实现方式：先把 ROI 之外像素涂黑，再裁剪车辆区域。否则会把画面里其它车
   （如正前方那辆大面包车）的车牌误当成目标车牌。实测未做此约束时，
   同一个非目标车牌被重复误报 4 次。

## 三、车牌格式约束

```
1 个汉字（粤、桂、京… 省份简称） + 6 或 7 位（大写英文 / 数字）
例：粤A1G0V91  粤AAR902  桂A7M7M4
```

人工审核时，「用户确认」栏必须符合此格式才能点「确认上报 → 是」。

## 四、人工审核流程

1. 打开 GUI → 要求提供**初成果存放路径**（不含中文）→ 校验后进入审核界面
2. 审核界面逐案例操作：
   - **检测车牌** / **置信度**：自动读取，**只读不可改**
   - **用户确认**：默认等于检测车牌，可修改，须符合车牌格式
   - **确认上报**：`是` / `否` / `跳过`
     - `是` = 确认该检测结果
     - `否` = 否认，后续不再出现
     - `跳过` = 暂不确认，可稍后回来
   - **上一张**：返回上一个案例
   - **转至未确认**：跳转到标记为「跳过」的案例；若无，提示「已全部确认」
   - **完成报告**：所有案例都已选「是」或「否」才可执行，否则提示「尚有未确认案例」
3. 填写**违法地点与行驶方向**（≤200 字，必填）后点「生成报告」，在初成果目录下生成 `人工审核结果/`：
   - 写入 `人工审核结果.csv`，**仅包含确认「是」的案例**（附材料清单）
   - `违章检测报告.html`（自包含：证据图 base64 内嵌，可单文件分发）
   - `违章检测报告_轻量版.html`（只有几 KB，图片走相对链接，本机浏览用）
   - 每个确认车牌的**同名文件夹**，把该案例的**三张证据帧**复制进来：
     - `NN_原图.jpg` —— 置信度最高那一帧（报告正文用的那张）
     - `NN_证据帧2.jpg` —— **最早附近**帧
     - `NN_证据帧3.jpg` —— **最晚附近**帧
   - 帧数不够的案例如实少给（例如只有一帧就只出 `原图.jpg`），**不拿同一帧凑三张**

> **分工**：三张证据帧在**第一步 Python** 就挑好、取好、按固定名放进
> `证据图/案例NN_车牌/`，审核程序只负责把**确认车辆**的那些图复制过来。
> 因此审核程序里没有选帧、没有图像处理，也没有文件名猜测。

## 六、时间字段的取法（两种模式）

时间列的语义取决于视频源，由 `make_outputs.py --time-mode` 决定：

| 模式 | 适用 | 时间来源 | 示例 |
|---|---|---|---|
| `clock`（默认） | 视频**带**记录仪 LCD 叠字 | 基准时间 + 视频内秒数 | `2023-03-04 15:38:02` |
| `video` | 视频**不带**叠字（如 B 站剪辑片段） | 视频内播放时间 | `00:02.3` |

`clock` 模式：实测叠字时间随视频秒数线性递增（t=0→15:38:02、t=10→15:38:13），
因此用「基准时间 + 视频内秒数」换算，比逐帧 OCR 精确且无误差。基准时间从首帧读取，
用 `--base-ts` 传入。

`video` 模式：直接写视频内播放时间（MM:SS.s），因为源视频没有可换算的绝对时钟。

CSV 列名统一为 `时间_起 / 时间_止`（另附 `时间类型` 列说明是哪一种），
避免下游（如审核 GUI）因模式不同而找不到列。

## 七、视频编码格式（重要，影响耗时几十倍）

**处理前必须确认编码格式。AV1 编码的视频会让整条流水线慢约 20 倍。**

实测对比（同一段内容、同为 1920×1080、同样采样 450 帧）：

| 编码 | 车辆检测 450 帧用时 | 速度 |
|---|---|---|
| H.264 | **22.8 秒** | 19.8 帧/秒 |
| AV1 | **> 962 秒（未跑完）** | ≈1.2 帧/秒 |

原因：AV1 软解本身贵，且**随机跳帧**（`cap.set(CAP_PROP_POS_FRAMES, fi)`）在 AV1 上
要从关键帧起解码整段，代价极高。

### 处理方式

**第 1 步：先统一转成 H.264。** 用项目自带 ffmpeg：

```
bin\ffmpeg.exe -y -i <原视频> -c:v libx264 -preset veryfast -crf 18 -c:a copy <输出>_h264.mp4
```

转码是无损感知的（crf 18），仅体积变大，帧数不变，因此**不影响检测结果**。

**第 2 步：识别阶段批量顺序读取，不做随机跳帧。**
`run_pipeline.py` 已实现：先算出所有轨迹要用到的帧号，排序后**单向顺序读取**一次取齐
（日志里的「预取 N 帧」）。即使已转 H.264，这一步也能再快一截。

### 怎么快速判断编码

```
bin\ffprobe.exe -v error -select_streams v:0 -show_entries stream=codec_name -of csv=p=0 <视频>
```

看到 `av1` 就先转码，不要直接跑。

## 八、注意事项（实测踩过的坑）

- **ROI 顶点必须做凸包重排**：手写/转录顶点极易乱序 → 多边形自相交 → 射线法判定全废
  （实测同样车框算出 0.00 重叠，跑出"0 条"）。
- **写图片到中文路径不能用 `cv2.imwrite`**：Windows 下会静默失败（返回 False 不报错），
  必须 `imencode` + 二进制写文件。
- **车牌识别要喂"车辆区域"而非紧裁车牌**：HyperLPR3 是场景图识别器，
  喂紧裁车牌会让它自己的检测头失效（返回空）。区域需外扩 + 放大。
  更稳的两段式做法：先用车牌检测器在车辆区域内定位车牌，再**围绕车牌裁一小块**
  放大后送识别。
- **证据图不能取轨迹首帧**：应急车道车辆刚进入画面时常只露车顶/侧面，车牌不可见。
  应在轨迹内按**车牌面积优先**选帧（面积与清晰度会相互抵消，清晰度权重不能高）。
- **案例数会因跟踪断裂而虚高**：车辆被遮挡或连续漏检超过阈值后轨迹断开新建 ID，
  同一辆车被拆成 2–4 条轨迹，若每条算一个案例就会重复上报。必须做轨迹归并
  （按车辆框位置判定同车，**不能只看车牌横向距离**——密集车流里相邻两辆车
  同时入画时车牌横向也可能很近）。
- **小目标是精度上限**：应急车道车辆的车牌常只有几十像素，省份字易错读。
  此时应输出 SUSPECT 交人工确认，**不要硬猜**。
- **归属判定不能只看底边重叠**：车辆压在 ROI 边界上时，底边稍越界就会被算成 0 重叠、
  整段被剔除（实测 t<2.2s 的目标车因此丢失）。宜用车辆框与 ROI 的面积交并比，
  或底边中点是否落入 ROI。
